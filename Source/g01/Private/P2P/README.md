# P2P role state synchronization

The lobby accepts incoming peer requests. After the authenticated peer and its datagram stream are ready, each client travels to `/Game/Maps/P2PLevel1`. The GameInstance client context retains the peer and datagram during travel; the game subsystem waits for the local Character and reattaches each retained peer in the new world. The link controller creates a remote copy and adds a state sender component to the local character. Sequence numbers are retained by the GameInstance across world changes. The component sends position, rotation and velocity at 15 Hz; the receiver rejects malformed and out-of-order packets. This is a prototype snapshot protocol: it does not yet provide interpolation, action-event delivery, prediction or authoritative validation.

`Content/NetConfig/conf_p2p.txt` is the peer engine configuration and is copied to a process/client-specific Saved directory when needed. It uses the lobby socket and does not need a certificate pin. It must contain a non-empty `[p2p] name` and `[lsquic_settings] es_datagrams=1`; both are needed by the SDK data stream. The locally configured `Content/NetConfig/hole_punching_config.txt` must specify the trusted lobby server's `server_cert_sha256` (64 hexadecimal SHA-256 digits); the helper requires a pinned lobby connection. Provision that fingerprint for the actual server before testing. The existing lobby configuration is local and ignored by git. Use lobby bind port 0 to let the OS select a different port for every client, including single-process PIE clients.

The current lobby UI automatically accepts incoming requests. Only direct connections are supported; relay results are rejected and released. Keep the lobby open while negotiating; once authenticated the peer survives independently of the lobby UI.

The lobby map does not need a Character. `P2PLevel1` uses `BP_DefGameMode`, which creates the local Character; the controller creates the remote representation after travel.

For a headless end-to-end check, build `g01Editor` with development automation enabled, then run `Tests/run_p2p_travel_smoke.py --editor <UnrealEditor-Cmd.exe> --server-dir <server-bundle>`. The server bundle needs the P2P helper executable, its DLLs, `conf.txt` and the test certificate/key matching the client's configured pin. The test starts an isolated helper server and two game processes, negotiates a peer connection, verifies travel and checks the other Character's position. It also displays a toast before travel, requests garbage collection in the new world and waits beyond the toast's timer. Its console command is compiled only with `WITH_DEV_AUTOMATION_TESTS`.
